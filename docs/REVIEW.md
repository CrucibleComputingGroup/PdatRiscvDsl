# Review of the CRISP revision

## 1) IMPORTANT CHANGES (must fix before submission)

The first five items below are resolved in the current revision. The last two
identify the remaining evidence and submission limits; the manuscript explicitly
avoids claiming that missing work is complete. Locations refer to section names
in the separate paper repository, so they survive pagination changes.

### Contract domain was narrower than the claimed contribution — resolved

- **Location:** original CRISP opening and “µArch Config File”; “The semantic
  domain ... maps an initial set ... to a final state.”
- **Category:** Consistency.
- **Issue:** encoding sets cannot represent operand values, sampled execution,
  or interface histories, although the paper claims all three constraint levels.
- **Fix:** replace the section with `src/crisp_language.tex`, defining the
  binding signature, assumptions, obligations, observations, and event types.
- **Rationale:** the language now has a semantic home for the advertised classes.
- **Confidence:** High.

### Range and re-inclusion semantics needed exact support — resolved in new path

- **Location:** original CRISP expression semantics; “encoding common prefixes
  for ranges”; legacy `codegen_v2_aig.py` include processing.
- **Category:** Logic.
- **Issue:** a single common prefix does not denote arbitrary intervals. Active
  legacy code also skips constrained inclusion and does not widen existing
  instructions on re-inclusion.
- **Fix:** compile policies to exact Boolean set operations and inclusive
  comparisons; retain the old path explicitly for historical runs.
- **Rationale:** the new denotation and its implementation agree on tested cases.
- **Confidence:** High.

### Types could be mistaken for preservation proofs — resolved

- **Location:** revised CRISP “Assumptions, Observations, and Cut Obligations”;
  “A candidate replacement checks the target's width and event”.
- **Category:** Logic.
- **Issue:** well-typed assumptions can be false, and a well-typed replacement
  can alter hardware behavior.
- **Fix:** retain the explicit relational preservation equation, reference-model
  interpretation of internal assumptions, and initialization/step/observation
  obligations. Candidates remain unproved in both text and generated manifests.
- **Rationale:** avoids circular or unsupported correctness claims.
- **Confidence:** High.

### Historical PPA could be misattributed to the new compiler — resolved

- **Location:** revised CRISP “Implementation and Validation Scope”; “The typed
  front end is opt-in.”
- **Category:** Consistency.
- **Issue:** the new compiler has language tests, while the existing numerical
  experiments were generated by the historical path.
- **Fix:** state this distinction in the implementation section and conclusion;
  preserve all existing numerical results.
- **Rationale:** no new experimental provenance is implied by the rewrite.
- **Confidence:** High.

### Semiformal discussion overclaimed correctness — resolved

- **Location:** Experimental Results, “Discussion”; “without sacrificing
  correctness guarantees for the constrained usage scenarios.”
- **Category:** Logic.
- **Issue:** that unqualified sentence conflicts with the paper's own bounded
  verification caveat and the revised preservation target.
- **Fix:** “The correctness evidence for each cut retains its stated scope:
  bounded checks do not establish unbounded preservation.”
- **Rationale:** a bounded pass must not be promoted to an unbounded theorem.
- **Confidence:** High.

### Actual typed-contract-to-cut integration remains incomplete — scoped limitation

- **Location:** revised CRISP “Assumptions, Observations, and Cut Obligations”;
  “records a pending preservation obligation.”
- **Category:** Other.
- **Issue:** the prototype does not generate and discharge a paired RTL miter
  from a candidate or certify a processor's semantic event bindings.
- **Fix:** keep the present limited implementation claim. For a stronger
  end-to-end language claim, add one real adapter, one proved generated cut,
  and an unsafe-cut negative control.
- **Rationale:** this is the largest remaining gap between the language and
  the pruning system, more useful to close than inventing extra syntax.
- **Confidence:** High.

### Publication readiness requires venue-specific checks — open

- **Location:** compiled full manuscript; new literature footnotes and class warnings.
- **Category:** Citations / Other.
- **Issue:** no page limit was supplied. The local TeX installation substitutes
  fonts and emits existing ACM metadata/accessibility warnings. New PL references
  are linked footnotes because editing BibTeX was prohibited.
- **Fix:** check the intended submission length and official fonts; convert the
  PL footnotes into formal bibliography entries when BibTeX edits are authorized.
  Verify ACM metadata and figure descriptions for the chosen submission mode.
- **Rationale:** a successful preview build is not a complete submission check.
- **Confidence:** High for the observed build limits; venue requirements unverified.

## 2) SUGGESTED CHANGES (polish / clarity / strength)

### Make one real scope boundary the language's evaluation example

- **Location:** CRISP “Typed Events and Value Refinements”; execution/retirement distinction.
- **Category:** Style.
- **Issue:** abstract typing rules are more persuasive with a concrete unsafe
  specification that would otherwise look plausible.
- **Fix:** use the existing speculative address-partition counterexample after
  validating its adapter; show the rejected retirement-scoped version beside
  the correct execution-scoped contract.
- **Rationale:** connects type checking to an actual pruning failure mode.
- **Confidence:** High.

### Add compact extension and annotation-cost evidence

- **Location:** CRISP “Reusable predicates” and implementation validation.
- **Category:** Other.
- **Issue:** the tests establish extension feasibility but do not quantify
  authoring effort or compare annotation cost with handwritten SVA.
- **Fix:** report the library definitions, binding declarations, and backend
  changes needed for the same two constraints; do not infer usability gains
  from syntax length alone.
- **Rationale:** provides a measurable extensibility argument without another
  physical-design run.
- **Confidence:** Medium.

## 5) FINAL “LOGIC COP” SUMMARY

- **Overclaims addressed:** the original encoding-set semantics did not support
  the full language claim; the unqualified correctness sentence exceeded bounded
  evidence; old PPA could have been mistaken for evaluation of the new compiler.
  Each now has a narrower replacement described above.
- **Arguments needing evidence:** correctness of real event bindings;
  completeness of the observation boundary; automatic discharge/composition of
  relational cut obligations. These remain integration tasks, not type-system results.
- **Reasoning inconsistencies addressed:** value refinements are separated from
  instruction bits; assertions remain obligations rather than assumptions; a
  finite passing trace or local SAT result is separated from induction/reachability.

Review limits: the new compiler and its tests were checked, but existing PPA,
the concurrent RSD case-study experiments, full processor proofs, and venue-specific
submission requirements were not independently revalidated. The literature
comparison is targeted, not an exhaustive novelty determination.
